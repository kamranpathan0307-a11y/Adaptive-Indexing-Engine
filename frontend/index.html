How Adaptive Indexing Works

The Adaptive Indexing Engine combines a B+ Tree and an AVL Tree to achieve optimal performance across cold and hot data access patterns by automatically migrating frequently accessed keys to a faster in-memory structure.

01

B+ Tree — Primary Storage

All key-value pairs are initially inserted into the B+ Tree. It provides efficient ordered storage with O(log n) lookup. Leaf nodes are linked sequentially, enabling fast range queries and full traversal.

02

AVL Tree — Hot Key Cache

Frequently accessed keys are promoted to the AVL Tree once their access count reaches the promotion threshold (default: 3 searches). The AVL Tree maintains strict balance factor |Δ| ≤ 1, guaranteeing O(log n) worst-case performance.

03

Promotion Mechanism

Every search increments the key's access counter in B+ Tree. When the counter reaches the threshold, the engine promotes that entry to the AVL Tree. Subsequent searches check the AVL Tree first, yielding faster average-case performance.

04

Visualization Guide

  • Teal circles — regular AVL Tree nodes
  • Amber circles — promoted (hot) keys in AVL Tree
  • h: / Δ: — node height and balance factor labels
  • Blue blocks — B+ Tree leaf node cells
  • → arrows — linked-list pointers between leaves
  • Scale pulse — one-shot animation on insert or search
